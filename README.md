# QueryPath — интерактивный тренажёр по SQL

Мини-клон формата Coddy (путь → практика → профиль), только для SQL. Чистый HTML/CSS/JS, без сборки — можно открыть локально или выложить на GitHub Pages.

## Запуск

Локально (нужен любой статический сервер, т.к. используются ES-модули):

```bash
cd sql-coddy
python3 -m http.server 8080
# открыть http://localhost:8080
```

### GitHub Pages
1. Залейте содержимое папки `sql-coddy/` в репозиторий.
2. Settings → Pages → Source: ветка `main`, папка `/ (root)`.
3. Готово — сайт появится на `https://username.github.io/repo/`.

## Структура

```

ai-worker.js            — Cloudflare Worker: общий прокси к Anthropic API для Индекс
js/main.js               — роутер (Путь / Практика / Магазин / Миссии / Профиль)
js/state.js               — прогресс, монеты, рубины, миссии, инвентарь (localStorage)
js/theme.js               — применение выбранной темы оформления
js/sqlEngine.js            — выполнение SQL через sql.js (SQLite в браузере)
js/pathPage.js, practicePage.js, profilePage.js, topbar.js   — экраны
js/shopPage.js             — магазин (аватары/рамки/темы), отдельная вкладка
js/missionsPage.js         — ежедневные миссии + ежедневная награда за вход, отдельная вкладка
js/settingsPanel.js        — единая панель настроек (открывается из Профиля)
js/lessonView.js, taskView.js, practiceTaskOverlay.js, aiAssistant.js — теория+тест+код, карточка задачи, ИИ-чат
data/lessons.js          — контент Пути (главы: теория, тест, задача)
data/practice.js         — банк задач для Практики
data/shop.js             — каталог магазина (5 обычных/5 редких/3 эпических/3 легендарных/2 мифических на категорию)
```

Все JS-файлы — плоским списком в одной папке `js/`, без вложенных подпапок: так их проще загружать по одной на GitHub через телефон (папка = один экран "Upload files").

## Как добавить новую главу в Путь

Откройте `data/lessons.js`, скопируйте объект `s1c1` целиком и измените:
- `id`, `chapter`, `title`
- `theory` — массив слайдов (`type: 'text'` с полем `html`, опционально `code`; или `type: 'table'`)
- `quiz` — вопросы `type: 'single'` (варианты + правильный индекс) или `type: 'fillblank'` (пропуски с вариантами)
- `task` — таблицы/датасеты и `solutionQuery` (эталонный SQL, с которым сравнивается ответ ученика)

## Как добавить задачу в Практику

Откройте `data/practice.js`, скопируйте один из объектов и измените поля (`topic`, `difficulty`, датасет, `solutionQuery`).

## Монеты

За урок начисляется:
- 0 ошибок (в тесте и в задаче) → **10 монет**
- 1 ошибка → **7 монет**
- 2+ ошибок → **5 монет**

Логика — в `js/components/lessonView.js`, функция `coinsForErrors`.

## ИИ-ассистент Индекс

Сайт статический, поэтому секретный API-ключ нельзя спрятать в браузере. Два варианта настраиваются в Профиле:

1. **Общий прокси (рекомендуется для тебя + близких)** — разверни `ai-worker.js` как бесплатный Cloudflare Worker (инструкция в начале файла), впиши его URL в Профиль → ИИ-ассистент. Один ключ на всех, никто его не видит.
2. **Свой API-ключ** — каждый человек вводит собственный ключ Anthropic в Профиле, ключ хранится только в его браузере.

## Структура пути (зигзаг)

Каждая обычная глава (не чекпоинт) рендерится как **3 отдельных узла**: Теория → Тест → Задача, друг за другом по горизонтали, с чередованием направления по рядам (змейка), как в оригинале. Чекпоинты («Трофей главы») остаются одним узлом с кратким повторным тестом.

Прогресс по каждой фазе хранится отдельно (`state.lessonPhases`), монеты начисляются один раз — при завершении фазы «Задача», с учётом ошибок, накопленных на тесте и в самой задаче.

## Типы вопросов в тесте

- `single` — выбор одного варианта из списка
- `fillblank` — заполнить пропуски в SQL-запросе, каждый пропуск — свой набор кнопок-вариантов
- `truefalse` — Истина/Ложь
- `findline` — кликнуть на строку кода с синтаксической ошибкой

## Структура главы (по образцу Coddy)

Каждый `Раздел` (SECTIONS) состоит из нескольких `Глав` — сгруппированы полем `module` у объектов в LESSONS. Путь автоматически рисует текстовый разделитель между главами (например «Введение» → «Условия»). Глава обычно заканчивается чекпоинтом (`kind: 'checkpoint'`) — трофей-нодой с обзорным тестом по всей главе.

## Практика: накопительные задачи

Банк практики (`data/practice.js`) организован так, чтобы после каждой новой темы в Пути появлялись задачи и на неё саму, и на неё в связке с ранее изученными темами (например «DISTINCT + WHERE», «AND + ORDER BY», «LIKE + IN + ORDER BY»). Чтобы добавить новую комбинацию, скопируйте существующий объект и укажите `topic` — тот же принцип, что и раньше.

## Монеты, рубины, миссии, магазин

- **Монеты** — за уроки на Пути (10/7/5 в зависимости от ошибок).
- **Рубины** — премиум-валюта. Начисляется за ежедневные миссии и ежедневную награду за вход (вкладка «Миссии»). 5 миссий в день (список — `js/state.js`, `DAILY_MISSION_DEFS`), у каждой своя награда, плюс бонус за выполнение всех пяти (`ALL_MISSIONS_BONUS`). Отдельно — лестница ежедневных наград на 7 дней, растущая вместе со стриком (`DAILY_REWARD_TABLE`), забирается раз в день.
- **Магазин** (вкладка «Магазин», `js/shopPage.js` + каталог `data/shop.js`) — три категории (аватары/рамки/темы), в каждой ровно 5 обычных, 5 редких, 3 эпических, 3 легендарных, 2 мифических айтема. common/rare/epic стоят монеты, legendary/mythical — рубины. Визуальная «крутизна» растёт вместе с редкостью (обычная рамка — простое кольцо, мифическая — анимированная радужная, см. классы `.rarity-*` и `.frame-rarity-*` в `style.css`). Бесплатные айтемы (без рамки, 5 базовых аватаров, тёмная и светлая темы) выданы всем по умолчанию.
- **Темы** переключаются мгновенно через CSS-переменные. Часть тем — полностью свои палитры (`theme-light/-sunset/-forest/-aurora/-nebula`), часть — «акцентные» перекраски базовой тёмной/светлой темы (`accent-*` классы) для дешёвого расширения ассортимента без дублирования полных палитр. Применяется через `js/theme.js` при загрузке и при покупке/выборе в магазине.
- **Настройки** — одна кнопка в Профиле открывает панель (`js/settingsPanel.js`) со всем сразу: имя, подтверждение ответа в тесте, ИИ-ассистент, обновление сайта.

## Новое: онбординг, устойчивость к сбоям, конфетти, звуки, недельный отчёт, финальный проект

- **Приветственный экран** (`js/onboarding.js`) — 4 слайда при первом запуске (монеты/рубины, стрик/уровень, магазин/миссии), пропускаемый, флаг `settings.onboardingSeen`. Повторно открыть — Настройки → «Как это работает?».
- **Защита от «пропавшего магазина»** — `index.html` теперь грузит `js/main.js` через `import()` (а не статический `<script type=module src=...>`), поэтому если какой-то файл не залит на GitHub, ловится ошибка и показывается понятный экран вместо пустой страницы. Плюс `try/catch` вокруг каждого рендера страницы в `js/main.js` — если один экран сломается, остальная навигация продолжит работать.
- **Skeleton-заглушка** — простой pulse-плейсхолдер в `index.html`, виден пока грузится JS.
- **Крупные ✓/✕ иконки** в фидбеке теста — не полагается только на цвет (важно для дальтоников).
- **Разные звуки** (`js/soundFx.js`) — `feedbackFx` (ответ), `levelUpFx` (новый уровень), `achievementFx` (ачивка/трофей) — три разных мелодии.
- **Конфетти** (`js/confetti.js`) — лёгкая CSS-анимация без зависимостей, запускается на трофей главы и левел-ап.
- **Отчёт «За эту неделю»** — блок в профиле, считает уроки/задачи/стрик за последние 7 дней из уже сохранённых данных.
- **Финальный проект раздела** — глава «Итоговый проект» в конце Раздела 1, одна большая задача на данных интернет-магазина, комбинирующая всё пройденное (WHERE+AND+LIKE+ORDER BY+LIMIT+арифметика).

## Раздел 2 и порядок дальнейших тем

По результатам поиска (DataCamp, SQLBolt, LearnSQL и др.) стандартный порядок изучения SQL после базового синтаксиса такой: **агрегатные функции → GROUP BY/HAVING → JOIN → подзапросы → оконные функции/CTE**. Раздел 2 сейчас начат с главы «Агрегатные функции» (COUNT, SUM, AVG, MIN, MAX). Следующие по очереди: GROUP BY/HAVING, затем JOIN (INNER/LEFT), затем подзапросы.

## Трофеи требуют использования всех функций главы

Каждая задача чекпоинта теперь проверяет не только правильность результата, но и что в запросе реально использованы все ключевые слова, пройденные в главе (поле `requiredKeywords` в `data/lessons.js`, проверка — `js/taskView.js`, функция `missingKeywords`). Если результат верный, но, например, не хватает `OR`, — покажется подсказка, чего не хватает. Проверка идёт по границам слов (regex `\b`), поэтому `IN` не сработает ложно на `in_stock`.

## Полы, реальные превью вещей, сортировка по редкости

- **Полы** — `state.inventory.gender`: Унисекс (по умолчанию, всё доступно) / Женский / Мужской. Селектор — чипы в редакторе аватара (`js/avatarEditor.js`). Платья (`excludeGender: 'male'` в `data/shop.js`) недоступны для мужского пола — показываются приглушённо с подписью «Недоступно для этого пола». Бороды в системе нет, поэтому обратное ограничение (женщинам нельзя бороду) не добавлял — добавить легко тем же способом, когда появится сам предмет.
- **Реальные превью** — `buildItemPreviewNode()` в `js/avatarRender.js` строит мини-аватар с надетой вещью (причёска/одежда на нейтральном теле, рамка на нейтральном аватаре) вместо плоского цветного квадрата. Используется и в редакторе аватара, и в основном магазине, и в модалке открытия сундука. Темы остались цветными образцами — их «не надевают» на персонажа, показывать нечего.
- **Сортировка по редкости** — кнопка «Редкость ↑/↓» (`sortByRarity()` в `data/shop.js`), работает в обоих местах (редактор аватара + основной магазин) для всех категорий кроме бустеров/сундуков.

## Полноэкранный 3D-просмотр персонажа (как в BG3/DOS2)

Клик по аватару в профиле теперь открывает `js/characterViewer.js` — полноэкранный вид на весь экран, тёмный градиентный фон, персонаж по центру. Один палец — поворот (с инерцией), два пальца щипком или колесо мыши — зум (0.7×–2.6×), можно приблизить и разглядеть детали причёски/одежды крупным планом. Кнопка «Изменить» ведёт в обычный редактор вещей. Честная оговорка: настоящей 3D-модели у нас нет (аватар — плоские CSS-слои), поэтому это иллюзия вращения (передняя и затемнённая задняя грань), а не полноценная 3D-геометрия с видом со всех сторон.

## Платья и кимоно/юката

Добавил **2 новые формы** одежды: `dress` (V-образный силуэт с золотой/цветной линией талии) и `kimono` (запашной силуэт с поясом-оби — используется и для кимоно, и для юката, различаются только цветом/узором). Пояс/линия талии строится отдельным элементом-«соседом», а не дочерним псевдоэлементом — учёл прошлый баг с обрезкой через `clip-path`. **19 предметов одежды** (было 8): 5 обычных, 5 редких, 3 эпических, 3 легендарных, 3 мифических (включая радужное «Аврора»-платье).

## Исправление причёсок + плавный поворот

Нашёл реальную причину нечёткости хвостов/пучка/косы: `clip-path` на родительском элементе обрезает **и его псевдоэлементы** (`::before`/`::after`), поэтому боковые «хвостики» просто вырезались вместе со всем, что выходило за пределы эллипса-«шапочки». Переделал `js/avatarRender.js` — составные причёски (хвост, два хвостика, пучок, коса) теперь строятся из настоящих дочерних `<div>` вместо псевдоэлементов, каждый со своим клипом/формой. Всё видно чётко.

Поворот в редакторе аватара теперь плавный: рендер через `requestAnimationFrame` (не напрямую в обработчике `pointermove`), инерция после отпускания (аватар докручивается и плавно тормозит за счёт затухания скорости), `touch-action:none` для нормальной работы на телефоне без конфликта со скроллом страницы. Превью увеличено с 140px до 190px.

По референсам (анимешные подборки мужских/женских причёсок) добавил **4 новые формы** силуэтов через CSS `clip-path`/псевдоэлементы: хвост (`ponytail`), два хвостика (`twintails`), пучок (`bun`), волны (`wavy`), плюс коса (`braid`) и андеркат (`undercut`) — итого 8 различных форм вместо прежних 4. Причёсок в магазине теперь **23** (было 8), с редкостью по своему усмотрению (простые перекраски — обычные/редкие, более сложные силуэты — эпические/легендарные, два радужных варианта — мифические). Не копия конкретных причёсок с картинок один в один — это невозможно с плоскими CSS-формами без лица, но по духу и вариативности вдохновлено референсами.

## Аватар без лица: причёски, одежда, коллекция

- **Редактор аватара** (`js/avatarEditor.js`) — открывается кликом по аватару в профиле. Три слоя: Тело (18 старых градиентных аватаров), Причёска, Одежда (8 предметов, стили `crew/hoodie/collar/cape`). Никаких лиц/глаз/рта — только силуэты, как просили.
- **Слои рендерятся** через `js/avatarRender.js` (`buildAvatarNode`) — переиспользуется в профиле и редакторе; тело+одежда+причёска накладываются друг на друга и обрезаются по кругу.
- **Коллекция** (`js/collectionPage.js`) — единый экран со всеми категориями (тело/причёски/одежда/рамки/темы), счётчик открытых предметов в каждой вкладке, заблокированные — с иконкой замка.

## Сложный режим уроков (два уровня сложности)

После полного прохождения обычного урока (все 3 фазы) под ним появляется четвёртый ряд — «🔥 [Урок] — сложнее». Это отдельный набор теории/теста/задачи (поле `hard` на объекте урока в `data/lessons.js`), с более подробными примерами, более каверзными вопросами и более сложной задачей — но без заумных терминов. Прогресс и монеты считаются отдельно от обычного урока (эффективный id `lessonId-hard`), даёт дополнительный бонус +10 монет за прохождение.

Реализовано для **19 из 20** обычных уроков — практически полное покрытие обоих разделов (Раздел 1 «Основы SQL» и Раздел 2 «Агрегатные функции»). Единственное исключение — «Финальный проект» (он и так уже итоговая комплексная задача, отдельная сложная версия ему не нужна). Проверено программно: `LESSONS.filter(l => l.kind==='lesson' && !l.hard)` возвращает только этот один урок.

## Редактор аватара: поворот и примерка

- **3D-подобный поворот** — потяните аватар в редакторе в сторону (мышью или пальцем), он «крутится» через CSS `perspective` + `rotateY` (лицевая и тыльная грань с затемнением, эффект вертящейся карточки). Это не настоящая 3D-модель (у нас плоские CSS-слои), но честно передаёт ощущение вращения.
- **Примерка недоступных вещей** — клик по любому ещё не купленному предмету (причёска/одежда/тело) сразу показывает его на превью-аватаре, без покупки. Появляется баннер «Примеряете: [название]» с кнопками «Купить» и «Снять примерку».

## Подключение Supabase (облачный аккаунт и синхронизация прогресса)

1. **Панель Supabase**: Settings → API — скопируйте Project URL и anon public ключ.
2. **SQL Editor** → New query — выполните `supabase-setup.sql` (файл в корне проекта): создаёт таблицу `sql_progress` с Row Level Security (каждый видит только свою строку).
3. Authentication → Providers — убедитесь, что Email включён.
4. В самом приложении: Профиль → Настройки → «Облачный аккаунт (Supabase)» — вставьте URL и ключ, нажмите «Подключить», затем зарегистрируйтесь/войдите по email.

После входа прогресс автоматически сохраняется в облако при любом изменении (`js/cloudSync.js`, `scheduleCloudPush`, дебаунс 2.5с) и подтягивается обратно при входе на новом устройстве (с подтверждением, если в облаке уже что-то есть). Ключи хранятся в `localStorage` — они публично-безопасны, реальная защита — через RLS-политику в базе.

Если используете один Supabase-аккаунт для нескольких сайтов — таблица уже названа с префиксом `sql_`, конфликтов с другими проектами не будет.

Если решите подключать аккаунты — Supabase-проекты изолированы друг от друга, использование того же аккаунта для двух разных сайтов безопасно (просто дайте таблицам этого проекта уникальный префикс, например `sql_users`, `sql_progress`, чтобы не пересекаться с таблицами другого сайта).

Если решите делать облачные аккаунты — вот актуальные варианты (2026):
- **Supabase** — на PostgreSQL (тематически ближе к SQL-курсу!), щедрый бесплатный тариф, авторизация + база данных из коробки, подключается прямо со статической страницы.
- **Appwrite** — открытый исходный код, тоже Docker/self-host или облако, похож на Firebase по набору функций.
- **PocketBase** — самый лёгкий вариант (один бинарник), но требует свой сервер (не подходит для чистого GitHub Pages без хостинга бэкенда).
- **Firebase** — по-прежнему хорош, особенно для мобильных сценариев и офлайн-синка.

Для этого проекта (SQL-тренажёр) больше всего подходит **Supabase** — и по бесплатному тарифу, и по духу (учим SQL — храним данные в настоящем PostgreSQL).

- **ИИ-ассистент переименован в «Индекс»** — везде (было Bugsy/Багси), включая system-промпт в `js/aiAssistant.js`.
- **Звук + вибрация** на ответ в тесте — `js/soundFx.js`, короткий бип через Web Audio API + `navigator.vibrate`, тумблер в Настройках (по умолчанию включено).
- **Заморозка стрика** — расходуемый товар в магазине (вкладка «Бустеры», 20 монет за штуку). При пропуске дня `Store.touchStreak()` в `js/state.js` автоматически списывает одну заморозку вместо сброса серии.
- **Экспорт/импорт прогресса** — Настройки → «Данные»: скачивает/загружает JSON-файл со всем состоянием (`Store.exportData()`/`Store.importData()`).
- **Личная статистика** — блок в Профиле: средняя точность уроков, среднее время урока, % задач практики, решённых с первой попытки — считается из уже сохранённых данных, без новой инфраструктуры трекинга.
- **Поиск в практике** — текстовое поле над фильтрами, фильтрует по названию задачи вживую.
- **Платная углублённая подсказка** — в задаче (`js/taskView.js`) кнопка «Полное решение · 5 монет» рядом с обычной бесплатной подсказкой — списывает монеты и показывает точный эталонный SQL.

## Новое: XP/уровень, ачивки, комбо, задача дня, работа над ошибками

- **XP и уровень** — начисляется вместе с монетами за уроки/практику (`Store.addXp`), уровень растёт по формуле `level × 40 XP`, прогресс-полоса в профиле.
- **Ачивки** (`data/achievements.js`) — 12 штук, проверяются функцией `check(state)` по уже сохранённым данным, без новой инфраструктуры трекинга. Отображаются сеткой в профиле, заблокированные — приглушены.
- **Комбо-бонус** — `Store.recordAnswer(isCorrect)` считает верные ответы подряд; каждые 5 подряд — баннер и +5 монет.
- **Задача дня** — `Store.getDailyTask()` детерминированно выбирает задачу практики по хэшу текущей даты; карточка на вкладке «Миссии», +15 рубинов при первом решении.
- **Разбор решения** — после верного ответа в задаче показывается блок «Почему это работает» (текст берётся из `task.hint`).
- **Автообъяснение через ИИ** — кнопка «Объяснить с Индекс 🔎» сразу в плашке с неверным ответом в тесте.
- **Работа над ошибками** (`js/mistakesReview.js`) — вопросы, где были ошибки, сохраняются (`Store.addMistake`/`getMistakes`); отдельный экран со списком, пересдать вопрос — он исчезает из очереди. Вход — с вкладки «Миссии».

- **Миссии** — ежедневные/еженедельные наборы задач, легко добавить как ещё один файл данных + экран, использующий тот же `state.completedPractice`/`completedLessons`.
- **Магазин** — трата монет (`Store.spendCoins`), уже готов в `state.js`, не хватает только витрины.
- Разделы 2+ (JOIN, GROUP BY, подзапросы...) — добавляются точно так же, как раздел 1.
